# Azure App Service の運用と公開手順

前半が現在の運用、後半が初回公開のときの手順（当時の記録）である。
運用は「方針（決まっていること）」「環境の値（出典と確認日つき）」「起動状態（変わるもの）」を分けて書く。

## 運用方針（決まっていること）

- `main` への push は本番デプロイと同じ。本人の承認を得てから行う
- Azure アプリの起動・停止は、本人が判断して行う
- `DATABASE_URL` と `OPENAI_API_KEY` は Azure の環境変数にだけ置き、GitHub や設定ファイルへ書かない
- 費用は、本人が Azure の「コスト管理と請求」で確認する。DB の記録などから請求額を断定しない
- 千人将以外のリソース（学校用の B1 など）とは、プランも費用も分けて扱う

## 環境の値（2026年10月10日に整理、10月14日に一部更新。値が変わったら、この節だけを更新する）

| 項目 | 値 | 出典・確認の状態 |
| --- | --- | --- |
| 千人将の本番 | Azure App Service「Project-senninsyou-app」 | デプロイ用ワークフローの設定（確認済み） |
| プラン | Free F1 | 本人の確認（2026年10月） |
| 学校用の B1 | 千人将とは別のリソース | 本人の確認（2026年10月） |
| アクセス制限 | Microsoft Entra ID による本人限定 | 2026年9月のクラウド公開時の記録。2026年10月13〜14日、サインインしていないブラウザで本番を開くと、Microsoft のサインイン画面へ遷移した（確認済み）。これはアプリが正常に動くことの確認ではない |
| 予算アラート | 設定の有無は未確認 | ポータルで本人が確認する |

## 起動状態

起動しているか停止しているかは変わるので、この文書には固定して書かない。必要なときにポータルで確認する。

- 停止中に開くと「Error 403 - This web app is stopped」と表示された（2026年9月、本人の報告）
- F1 には1日の CPU 時間の上限があり、上限に達した場合も停止することがある（Microsoft の説明による。千人将で起きたかは未確認）

## デプロイの流れ（ワークフローの設定で確認済み）

- `main` へ push すると、GitHub Actions「Build and deploy JAR app to Azure Web App」が動く
  - build：`mvn clean install`（`src/test` の自動テストも実行され、失敗するとデプロイしない）
  - deploy：Azure へログインし、`app.jar` を本番へ配置する
- `main` 以外のブランチへ push すると、「Test only (no deploy)」が `mvn -B test` だけを実行する。デプロイはしない
- デプロイの成功と、本番の画面が正しく動くことは別である。画面の動作は本人が確認する

## 戻し方

- 確実な方法：問題のあるコミットを取り消すコミットを作り、承認を得て `main` へ push する（デプロイが1回動く）
- 補助の方法：GitHub Actions で、前回成功したデプロイの実行を再実行する。元のコミットで動くが、再実行できる期限があり、Azure への再配置の成功は保証されない
- すぐにアクセスを止めたいとき：本人がポータルでアプリを停止する。データは Neon に残る。DB は削除しない

## 初回公開の手順（2026年9月14日の記録。当時の内容のまま）

この節は最初に公開したときの手順である。現在のデプロイは上の「デプロイの流れ」のとおり GitHub Actions で行う。

### 先に知っておくこと

- 公開先は Azure App Service（Linux / Java 21 / Java SE）を使用する。
- 最初は学習・動作確認用の Free F1 を使う。F1 は CPU 60分/日などの制限があり、常時稼働や本番運用向けではない。
- 学校課題用の学生クレジットを守るため、画面上の見積額が `0` でないプランは作成しない。Free F1 が選べない場合は、その場で作成を中止する。
- `DATABASE_URL` と `OPENAI_API_KEY` は Azure の環境変数へ登録し、GitHub や設定ファイルへ書かない。
- URLを第三者へ開放する前に、App Service の認証を必ず有効にする。

### 1. 公開用 JAR を作る

PowerShell でプロジェクト直下へ移動し、次を実行する。

```powershell
mvn clean package
```

成功すると、次の実行可能 JAR が作られる。

```text
target/project-senninsyou-1.0-SNAPSHOT.jar
```

### 2. Azure App Service を作る

作成前に「コスト管理と請求」で少額の予算アラートを設定する。目安は月額 `$1`（または現地通貨相当）で、通知先は自分のメールアドレスにする。これは利用停止装置ではなく、異常を早く知るための通知である。

Azure Portal で「Web App」を新規作成し、次を選ぶ。

| 項目 | 設定 |
| --- | --- |
| 公開 | コード |
| ランタイム スタック | Java 21 |
| Java Web サーバー スタック | Java SE（埋め込み Web サーバー） |
| オペレーティング システム | Linux |
| リージョン | Japan East または近いリージョン |
| 価格プラン | 最初は Free F1 |

「確認および作成」の画面で、月額見積もりが `0` であることを確認してから作成する。有料プランへの変更、追加ストレージ、Application Insightsなどの追加課金機能は今回は有効にしない。

Web App 名は Azure 全体で重複しない名前にする。作成後のURLは次の形式になる。

```text
https://<Web-App名>.azurewebsites.net
```

### 3. 秘密情報を Azure に登録する

作成した Web App の「設定」→「環境変数」→「アプリ設定」で、次の2件を追加する。

| 名前 | 値 |
| --- | --- |
| `DATABASE_URL` | ローカルで使用している Neon の接続URL |
| `OPENAI_API_KEY` | OpenAI APIキー |

値を画面共有、スクリーンショット、GitHub、チャットへ貼らない。保存すると Web App が再起動する。

### 4. JAR を配置する

Azure Portal の Web App からデプロイ機能を使い、手順1で作った JAR を配置する。Azure CLIを使う場合は、ログイン後に次を実行する。

```powershell
az webapp deploy --resource-group <リソースグループ名> --name <Web-App名> --src-path target/project-senninsyou-1.0-SNAPSHOT.jar --type jar
```

コマンド中の `<...>` は実際の名前へ置き換える。秘密情報はコマンドへ含めない。

### 5. 認証を有効にする（公開前に必須）

Web App の「設定」→「認証」から ID プロバイダーを追加する。

推奨設定：

- ID プロバイダー：Microsoft
- 認証：認証を要求する
- 認証されていない要求：HTTP 302 リダイレクト
- アカウント範囲：自分が使用する Microsoft アカウントに合う範囲

認証だけでは「ログインできる全ユーザー」を自動的に自分1人へ限定できない構成もある。最初は組織の単一テナント設定を優先し、シークレットモードで別アカウントが入れないことを確認する。

### 6. スマートフォン実機テスト

PCとは別の通信（スマートフォンのモバイル回線）で公開URLを開き、次を確認する。

1. 未ログインではアプリ本体が表示されない
2. 自分のアカウントでログインできる
3. 司令本部の4画面を移動できる
4. 任務を登録・更新できる
5. 機会を登録し、任務へ関連付けられる
6. 戦果を記録できる
7. AI将軍へ1回だけテスト命令を送り、回答が表示される
8. PCを終了してもスマートフォンから開ける

### 7. 公開後の確認

- Azure のログに `DATABASE_URL` や APIキーそのものが出ていない
- Git の変更一覧に `.env` が含まれていない
- OpenAI の利用量を確認し、想定外の増加がない
- F1 の制限で停止や遅延が目立つ場合のみ、有料プランを検討する
- Azure Cost Management で今月の実コストが `$0` のままか確認する

### ロールバック

公開に問題がある場合は、Web App を停止して第三者からのアクセスを止める。データは Neon に残るため、Web App の停止だけでデータベースを削除しない。
