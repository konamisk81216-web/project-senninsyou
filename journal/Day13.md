# Day13 - UI調整とAzureクラウド公開

## 今日の目的

司令本部を実用的な画面へ整理し、Project千人将を安全にクラウド公開する。

---

## 今日できたこと

### 1. 司令本部UIの調整

- 司令本部、任務管理、機会レーダー、収益・戦果を画面分割
- 売上速報と優先任務を司令本部へ集約
- AIクイックコマンドと任務優先度を色分け
- AI回答を状況、収益判断、戦果評価、次の任務に構造化
- 「新しい市場を探す」を追加し、新規事業や成長市場も提案対象にした
- 次の任務が空の場合は登録ボタンを表示しないよう調整

### 2. Azure App Service向けの準備

- Azure指定ポートで起動できるよう設定
- デプロイ・再起動時の安全な終了処理を追加
- Azure公開手順を文書化
- 秘密情報をGitへ保存せず、Azureの環境変数として管理

### 3. 無料構成でクラウド基盤を作成

- Azure for StudentsとFree F1プランを使用
- Japan WestにApp ServiceとWebアプリを作成
- NeonとOpenAIの接続情報を環境変数へ設定
- 予算アラートを用意して学習用クレジットを保護

### 4. 本人限定のMicrosoft認証

- Microsoft Entra ID認証を有効化
- 学校テナントと本人のオブジェクトIDにアクセスを限定
- 未認証アクセスをMicrosoftログインへリダイレクト

### 5. GitHub Actionsによる自動デプロイ

- GitHubとAzure App ServiceをOIDCで接続
- ユーザー割り当てIDを利用
- `main`へのpushで自動ビルド・自動デプロイする構成を完成

### 6. 本番環境のHTTP 400を解決

- Azure認証後の情報がTomcatの既定ヘッダー上限を超える問題を確認
- HTTPリクエストヘッダー上限を64KBへ拡張
- 再デプロイ後、クラウド上で司令本部の正常表示を確認

---

## 発生した問題と解決

- Japan Eastの作成拒否：許可対象のJapan Westへ変更
- OIDC設定失敗：GitHub Actionsを許可し、GitHubを再接続
- ロール割り当て重複：新規IDではなく作成済みIDを再利用
- 認証後の403：本人のオブジェクトIDを登録
- 認証後の400：TomcatのHTTPヘッダー上限を拡張

---

## Day13の到達点

- クラウド上で正常起動
- 秘密情報をGitへ保存せずに運用
- 本人限定認証を実現
- GitHubからAzureへの自動デプロイを実現
- PC・スマートフォンから利用できる状態を完成

Project千人将は、ローカルPC上の開発アプリから、どこからでも利用できる1人会社AI OSへ進化した。
